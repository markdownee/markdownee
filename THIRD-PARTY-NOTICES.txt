Markdownee third-party notices

This file records notices for third-party material distributed with Markdownee
whose text reaches no artifact by any other route. Markdownee itself is
licensed under Apache-2.0; see LICENSE.

Scope. Markdownee's Apify Actor image vendors a `pnpm deploy --prod` tree as
real files, so each vendored package's own LICENSE, NOTICE or COPYING file
travels inside the image beside the package it belongs to. The npm package
carries this notice while declaring its runtime dependencies separately. The
native Python wheel and source distribution declare their dependencies separately
and carry their own package-local LICENSE and NOTICE; they ship neither this file
nor the Node dependency tree. References below to the former markdownee-0.4.14
wrapper wheel are historical measurements; this scope correction does not change
the notices or source offers applicable to previously distributed artifacts.

This file therefore carries only what such a file cannot: an Apache-2.0 §4(d)
attribution notice, texts belonging to components bundled by a dependency rather
than vendored as packages, components that ship no licence text of their own, and
positions this project records rather than resolves. It also carries the two GNU
copyleft texts and the written offer of Corresponding Source that the vendored
libvips binary needs and publishes nowhere itself.

This file carries no per-package inventory of the vendored closure. Licence terms
must be checked against the dependency tree actually distributed; the historical
measurements below do not establish the contents of a later build.

No text below is reconstructed, paraphrased or inferred. Where a component's
notice text is not published by its author, that absence is recorded as an
absence rather than filled. Where it is published, it is sourced from a published
copy and verified against a second one, never written out from memory.

Playwright (Apache-2.0) — §4(d) attribution notice
================================================================================

`playwright` and `playwright-core` are the only vendored packages that ship a
NOTICE file. Both are vendored unmodified. Their §4(c) and §4(d) obligations are
discharged on either characterisation of what these artifacts are, so the
characterisation itself is not decided here:

  * Apache-2.0 §4(d) applies to "any Derivative Works that You distribute", and
    asks for the attribution notices "in at least one of the following places",
    the first being "within a NOTICE text file distributed as part of the
    Derivative Works". If a Markdownee artifact is a Derivative Work of these
    packages, this file is that NOTICE text file and the text reproduced below is
    that readable copy. The unmodified upstream NOTICE also travels in place,
    inside each package's own directory.

  * Apache-2.0 §1 excludes from "Derivative Works" those "that remain separable
    from, or merely link (or bind by name) to the interfaces of, the Work". A
    package copied whole and unmodified into node_modules, keeping its own
    directory, LICENSE and NOTICE, and imported by name, is what that exclusion
    describes. On that reading §4(d) does not attach at all, and nothing is owed.

  * Apache-2.0 §4(c) requires retaining "all copyright, patent, trademark, and
    attribution notices from the Source form of the Work". The vendored copies are
    unmodified, so every such notice is retained in place on either reading.

Either way the notices are carried, so nothing turns on which reading is correct.
Owner decision of 2026-08-27, on the same template as the got-scraping reading
below. This is the project's reading of the licence text, not legal advice.

playwright-core@1.62.1:

unavailable. Its manifest declares `"license": "Apache-2.0"` and `"files": ["dist"]`.

No text is written for it, and none is owed:

  * Apache-2.0 §4(a) requires that recipients be given "a copy of this License".
    That is the licence instrument itself, which is invariant and carries no
    copyright holder or per-package content. This distribution already carries it:
    Markdownee is licensed under Apache-2.0 and its own LICENSE is the full
    verbatim text, which travels in the npm tarball at package/dist/LICENSE and
    in the Actor image at /usr/src/app/LICENSE. These distributions carry a copy
    of the Apache-2.0 licence, and §4(a) asks for a copy, not a per-package copy.

  * Apache-2.0 §4(d) applies only "If the Work includes a NOTICE text file as part
    of its distribution". `got-scraping` publishes none, so the obligation does not
    arise.

  * Apache-2.0 §4(b) requires retaining copyright notices carried in the Source
    form. `got-scraping` carries none to retain.

--------------------------------------------------------------------------------

MIT and ISC condition redistribution on the copyright notice and permission text
travelling with the copy. For the three reproduced above, that text now travels in
this file. The upstream omission is in their npm tarballs rather than in their
projects, so this reproduces what those projects publish rather than curing
anything on their behalf.

`launder` is a fifth package of this kind and is deliberately NOT in the section
above, because it is not in the artifact at all. It declares MIT and ships no
copyright-and-permission notice in any of its 19 published releases, and
`sanitize-html` requires it from 2.17.4 onward. The project workspaces that build
the npm bundle and Actor image resolve a licence-clean replacement in its place
through a pnpm override scoped to `sanitize-html`, so the notice-less package is
neither bundled nor redistributed by those channels.

That replacement is not a copy of `launder`. It reimplements the one export
`sanitize-html` imports (`naughtyHref`), ported from `sanitize-html@2.17.3` — the
last release carrying the check inline, before the maintainer extracted it — with
that release's own MIT text and copyright line reproduced in the file. Its
`dayjs` dependency, unused by that export, leaves the graph with it.

The distinction from the four above is the availability of a remedy, not the
boundary — and the remedies differ in kind, which is why `launder` is recorded
here rather than beside them. For the three reproduced above, the remedy was
*obtaining* the text their projects publish outside the npm tarball. For
`got-scraping`, nothing was owed. For `launder` neither route is open: no text is
published at any source, so obtaining is impossible and composing one would be
fabrication. What remains is not shipping it, and a cure exists — so it was
applied rather than recorded.

This paragraph records the position because the absence would otherwise be
unexplained: a reader comparing the vendored tree against `sanitize-html`'s
declared dependencies will not find `launder`, and that is by design.
