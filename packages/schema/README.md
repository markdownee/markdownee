# `@markdownee/schema`

This package defines the shared Zod 4 input and output contracts and their TypeScript types.
`MarkdowneeInput` describes settings; `MarkdowneeOutput` distinguishes success, failed,
and skipped records. Apify presentation hints live in `apifyRegistry`, typed as
`z.registry<ApifyMeta>()`, separately from ordinary schema validation.

Generators project these definitions into ten committed artifacts: four Actor schema files
and six standalone schema/presentation exports. CLI, library, and Actor projections expose the
controls supported by their interfaces and storage models.

Markdownee is built on
[Trafilatura Core](https://www.trafilaturacore.com/)
(extraction) and [Crawlee](https://crawlee.dev/) (TypeScript crawler driving
Playwright); this package defines the shared input and output contracts for both surfaces.

Images accept `exclude`, `alt-text`, `resolved-url`, or `save`. Links, tables, and user-comment
sections accept `include` or `exclude`. Extracted format selectors are `txt`, `markdown`, `html`,
and `minified-html`; the compact HTML result key is `minifiedHtml`. Choose `minimal`, `standard`,
or `enhanced` for `outputLayout`, independently of format selection; `minimal` is the default.

## Local prerequisites

- **Node 22+**, **pnpm 10+**.

## Local development

```bash
pnpm install
pnpm --filter @markdownee/schema build
```

## Exports

- `MarkdowneeInput` — `z.ZodObject` schema describing every input field
- `MarkdowneeInputType` — `z.infer<typeof MarkdowneeInput>`
- `SAVE_ROUTE_TOKENS` / `SaveRoute` — the canonical `format-destination` save-token tuple and its inferred union type (source of truth for the `save` enum)
- `MarkdowneeOutput` — `z.discriminatedUnion('status', …)` over the `success` / `failed` / `skipped` dataset records
- `MarkdowneeOutputType` — `z.infer<typeof MarkdowneeOutput>` (3-member union)
- `apifyRegistry` — the typed `z.registry<ApifyMeta>()` carrying the Apify-only UI hints (`editor`, `prefill`, `enumTitles`, `sectionCaption`, …), attached per field via `.register(apifyRegistry, { … })`
- `ApifyMeta` — the type of those per-field Apify UI hints
- `OutputViews` / `KvsCollections` — typed Apify presentation config (Console views, output links, KVS collection key-prefixes)
- `toApifyInputSchema` / `writeApifyInputSchema` — pure converter + writer for the Apify INPUT_SCHEMA dialect
- `toDatasetSchema` / `writeDatasetSchema` — `MarkdowneeOutput` + `OutputViews` → `dataset_schema.json`
- `toOutputSchema` / `writeOutputSchema` — `OutputViews` → `output_schema.json`
- `toKeyValueStoreSchema` / `writeKeyValueStoreSchema` — `KvsCollections` → `key_value_store_schema.json`
- `toCliInputSchema` / `writeCliInputSchema` and `cliSurface` / `toCliSurface` / `writeCliSurface` (plus `cliOptionDescription`, `CLI_INPUT_SCHEMA_ID`) — the standalone CLI surface → `cli-input.schema.json` + `cli-surface.json`
- `MarkdowneeLibraryInput`, `toLibraryInputSchema` / `writeLibraryInputSchema`, `toSharedOutputSchema` / `writeSharedOutputSchema` (plus `LIBRARY_INPUT_SCHEMA_ID` / `SHARED_OUTPUT_SCHEMA_ID`) — the library surface → `library-input.schema.json` + `output.schema.json`
- `toFieldPresentation` / `writeFieldPresentation` and `toFormatPresentation` / `writeFormatPresentation` — typed field/format presentation documents → `field-presentation.json` + `format-presentation.json`
