The npm package provides [Markdownee](https://www.markdownee.com)'s CLI and
[Library API](#library-api). Use it to collect web content for research, search,
retrieval, or dataset preparation. It can return plain text, Markdown, readable
HTML, compact HTML, and the crawler's original capture. These representations
serve different consumers; inspect a sample before relying on an extraction.

[Trafilatura Core](https://www.trafilaturacore.com/) processes the supplied HTML
offline. [Crawlee](https://crawlee.dev/) handles fetching with Playwright or
HTTP-only Cheerio. The adaptive crawler uses browser rendering by default;
a positive `renderingTypeDetectionRatio` enables detection of pages that can
use HTTP. Explicit Chromium, Firefox, and Cheerio choices are also available.

Choose storage when collection and export should happen separately. `crawl`
writes records and content, `export` turns stored results into named files and
a manifest, and `purge` deletes the selected local buckets. For one URL,
`fetch` writes directly to stdout or files without opening Dataset/KVS
storage. Its image-save mode can create a sibling assets directory for
derived Markdown and HTML files.

In Node.js, `createCrawler(...).run(urls)` returns in-memory crawl results;
`fetch(url)` returns a single page's format map. Both use camelCase
options, with different subsets for their execution models. Link selectors,
URL patterns, limits, session controls, extraction policy, and output
destinations let you tailor the run. Start with a supported Node.js release and
install a Playwright browser only for a browser-capable crawler.

## Installation

```bash
npm install @markdownee/markdownee # local: library use
npm install -g markdownee     # global: the CLI on your PATH
npx playwright install chromium  # browser crawlers only
```

Provision Chromium for adaptive/Chromium crawling or Firefox for the Firefox
crawler. HTTP-only Cheerio does not need a browser. For an on-demand command,
`npx` uses an available package or downloads it to npm's cache:

```bash
npx markdownee fetch https://www.iana.org/help/example-domains \
  --crawler-type cheerio
```

The command sends Markdown to stdout and diagnostics to stderr. Trimmed example:

```markdown
# Example Domains

As described in [RFC 2606](https://www.iana.org/go/rfc2606) and
[RFC 6761](https://www.iana.org/go/rfc6761), a number of domains such
as example.com and example.org are maintained for documentation
purposes. These domains may be used as illustrative examples in
documents without prior coordination with us. They are not available
for registration or transfer.
```

## Usage

Choose the subcommand for the required destination:

```bash
markdownee crawl [URLS...]
markdownee fetch <url>
```

```bash
markdownee crawl https://example.com
markdownee crawl https://example.com --mode precision \
  --save minified-html-kvs
markdownee crawl https://example.com --save markdown-dataset
markdownee crawl --config-file config.json --max-requests-per-crawl 10
markdownee fetch https://example.com/ | less
```

Readable and compact HTML are separate output choices:

```bash
# Readable generated HTML.
markdownee fetch https://example.com/ \
  --save html-stdout

# Compact generated HTML and Markdown together.
markdownee crawl https://example.com/ \
  --save minified-html-kvs --save markdown-kvs

# Request both generated HTML presentations.
markdownee fetch https://example.com/ \
  --save html-file --save minified-html-stdout -o page
```

Both presentations use the selected layout. `original` contains the crawler
capture before content extraction, potentially after rendering, serialization,
or consent handling. When Markdown discovery supplies the source, original
HTML is derived from that representation and `markdownSource` records it.

## Subcommands

### `crawl`

Collect starting URLs into local storage. Success records contain per-format
hashes and UTF-8 byte counts, plus inline `content` for dataset routes or a
`key` for KVS routes. A format can use both destinations. Failed requests
are recorded after retries; `--store-skipped-urls` also records skips.
A failed request makes the command exit `2` while retaining successes.

```bash
markdownee crawl https://example.com
markdownee crawl https://example.com \
  https://www.iana.org/help/example-domains --save txt-kvs
markdownee crawl --start-urls-file urls.txt --storage ./my-archive

# markdown to both the dataset and the KVS, raw HTML to the KVS
markdownee crawl https://example.com \
  --save markdown-dataset --save markdown-kvs \
  --save original-kvs
```

Use `--start-urls-file` for a line-delimited URL file and repeat `--save` for
format/destination pairs; `markdown-kvs` is the default. `--storage` selects
the run's default buckets. `--purge` deletes those buckets before extraction.

### `fetch`

Fetch one URL without link following. The default `markdown-stdout` route
writes content to stdout; logs and progress use stderr. File routes persist
their outputs directly, without opening Crawlee storage.

```bash
markdownee fetch https://example.com/ | less
markdownee fetch https://example.com/ --save txt-stdout > body.txt

# → report.md
markdownee fetch https://example.com/ \
  --save markdown-file -o report

# → out/page.md + out/page.min.html
markdownee fetch https://example.com/ \
  --save markdown-file --save minified-html-file -o out/page

# → URL-slug names in snapshots/; original tagged .original.html
markdownee fetch https://example.com/ \
  --save html-file --save original-file -o snapshots/

# → out/page.md + out/page.html + out/page.min.html
#   (+ out/page.assets/ once the page has images that survive extraction)
markdownee fetch https://example.com/ \
  --image-handling save \
  --save markdown-file --save html-file --save minified-html-file -o out/page
```

Repeat `--save` with `txt`, `markdown`, `html`, `minified-html`, or `original`
and a `file` or `stdout` destination. Only one format can use stdout.
`--image-handling save` requires every route to be a file and at least one
derived Markdown or HTML format. It writes `<output-stem>.assets/` and rewrites
derived references to relative POSIX paths, leaving the captured original alone.

`-o, --output` is a literal filename for one format, a prefix for multiple
formats, or a directory when it ends in a slash or names an existing directory.
A filename without an extension receives the format suffix. Without an output
path, URL-derived names are written in the current directory.

Single-page flags such as `--crawler-type`, `--proxy`, `--mode`,
`--wait-for-selector`, and `--cookies` apply here. Crawl/storage flags such as
`--globs`, `--max-crawl-depth`, `--storage`, and `--session-pool-name` do not.
Exit `0` means success, `1` a hard failure, and `2` a requested format with no
content; available requested files are still written.

### `export`

Read stored success records and write their available formats, resolving KVS
keys when needed. Filenames derive from title, URL, then `page`. The manifest
includes all record outcomes; each success entry lists relative file paths.

```bash
markdownee export                 # → ./markdownee-output
markdownee export --output-dir ./out --storage ./my-archive
```

`--output-dir` defaults to `./markdownee-output`. `--storage` selects the
buckets to read.

### `purge`

Remove `datasets/`, `key_value_stores/`, and `request_queues/` beneath the
resolved storage directory. This is the same cleanup as `crawl --purge`.
**Deletion is permanent, with no confirmation prompt or undo.**

```bash
markdownee purge                          # purge the resolved storage dir
markdownee purge --storage ./my-archive   # purge a specific storage dir
```

## Storage directory resolution

The first available value wins:

- `--storage`
- `MARKDOWNEE_STORAGE_DIR`
- `CRAWLEE_STORAGE_DIR`
- `./storage` when `.actor/` or `./storage/` exists in the current directory
- `${XDG_DATA_HOME:-~/.local/share}/markdownee/storage`

## JSON config

Pass `--config-file path/to/config.json` for a camelCase configuration validated
by [the shared schema](https://github.com/markdownee/markdownee/blob/main/packages/schema/README.md).
Its field vocabulary follows the
[Actor input](https://apify.com/markdownee/crawler/input-schema?fpr=glueo),
but the CLI uses its own storage model. `datasetName`, `keyValueStoreName`,
and `requestQueueName` are parsed but ignored; `--storage` selects default buckets.
Supply CLI orchestration flags `--proxy`, `--purge`, and `--storage` on the command line.

JSON `startUrls` entries use `{ "url": "..." }` objects. JSON `globs` and
`exclude` use `{ "glob": "..." }` objects; their CLI flags use bare strings.

```json
{
  "startUrls": [{ "url": "https://example.com" }],
  "headless": false,
  "maxRequestsPerCrawl": 10,
  "mode": "recall",
  "imageHandling": "resolved-url",
  "save": ["txt-dataset", "original-kvs"]
}
```

Schema defaults are applied first, then config-file values, then explicit CLI
arguments. Unknown keys fail input validation.

## Output layouts

`outputLayout` controls generated structure independently of extraction,
destinations, and captured original HTML:

- `minimal`, the default, emits TXT/Markdown bodies and HTML fragments.
- `standard` adds flat YAML front matter and complete HTML documents with
  ordinary metadata. TXT front matter is a Markdownee convention.
- `enhanced` includes additional allowlisted metadata and crawl information.

Unavailable optional values and empty optional objects are omitted. The record
keeps the request `url` at top level and the final URL at `crawl.loadedUrl`.
Use `--output-layout` in the CLI or `outputLayout` in JSON/library options.

## Markdown discovery

`--markdown-discovery`, or `markdownDiscovery` in JSON and library calls,
selects how to look for an origin-published representation. Accepted Markdown
supplies content for all requested formats.

| Mode        | Additional discovery step                                        |
| ----------- | ---------------------------------------------------------------- |
| `off`       | None; retain ordinary HTML fetching                              |
| `alternate` | Follow up to three advertised same-origin Markdown links         |
| `negotiate` | Also request Markdown through Accept, with a refetch when needed |
| `probe`     | Also try a .md sibling URL                                       |

Links can come from `<link rel="alternate" type="text/markdown">` or an
equivalent response `Link` header. The steps are cumulative where the crawler
path supports them. Robots.txt checks can add an origin-level request;
per-origin budgets restrict unsuccessful attempts. Failed fetches or rejected
representations fall back to HTML extraction.

Accepted bodies require a successful response, a Markdown or `text/plain`
content type, and validation. Their derived HTML is cleaned before conversion.
`markdownSource` identifies the source. Link following uses available page
HTML; a response that is itself Markdown provides no HTML links to enqueue.

```bash
markdownee crawl https://docs.example.com \
  --markdown-discovery alternate
```

## Library API

Create a crawler and run a URL list:

```typescript
import { createCrawler, Deduplication, Save } from '@markdownee/markdownee';
import { Configuration, KeyValueStore } from '@markdownee/markdownee/storage';

const crawler = createCrawler({
  save: [Save.TxtKvs],
  includeHtml: false, // default — omit raw HTML from returned records
  deduplication: Deduplication.Minimal,
  maxResultsPerCrawl: 10, // bounds the in-memory result set (0 = unlimited)
});

const { dataset, statistics, failures } = await crawler.run([
  'https://example.com',
]);

const { requestsFinished, requestsFailed } = statistics;
console.log(`finished=${requestsFinished} failed=${requestsFailed}`);

console.log('Failed URLs:', failures.map((failure) => failure.url));

// Visit collected in-memory records, or grab the full array:
await dataset.forEach((record, i) => {
  console.log(i, record.url, 'depth:', record.crawl?.depth);
});
const all = dataset.export(); // LibraryRecord[]

// Optionally export to an explicitly selected Crawlee store:
const store = await KeyValueStore.open('default', {
  config: new Configuration({
    storageClientOptions: { localDataDirectory: './results' },
    purgeOnStart: false,
  }),
});
await dataset.exportToJSON('results.json', store);
await dataset.exportToCSV('results.csv', store);
```

The returned dataset contains successes; `failures` identifies exhausted requests
with their URLs, error messages, and retry counts. Statistics report request outcomes,
not the number of extracted records or skipped URLs.
Partial page failures do not discard the successful results or call
`process.exit()`. Options use the JSON contract's camelCase names and `SaveRoute`
format/destination values.

Library-only settings include `includeHtml` (default `false`), `storageDir`
for additionally writing full records to disk, and `logLevel` (default `warning`).
Limit in-memory result counts to suit the available memory; writing storage
does not eliminate the memory used by returned results.

Options are validated and copied when constructing the crawler. Each `run`
owns its queue, deduplication state, and logger; repeated or concurrent calls can
process the same URL. Calls without `storageDir` use memory storage, except that
explicit image `save` persists image bytes in the CLI's resolved default storage.
Read those image keys using `KeyValueStore` from `@markdownee/markdownee/storage`. With a
directory, result records accumulate there; callers sharing a directory share
its stored data. Dataset JSON/CSV exports require an explicit store. Invalid
options and run-level failures throw; partial page failures resolve.

Use `proxyConfiguration: { proxyUrls: [...] }` for HTTP, HTTPS, SOCKS4, or
SOCKS5 proxies. Apify Proxy integration belongs to the Actor.

### Single page: `fetch`

Return one URL's formats without persistent output:

```typescript
import { CrawlerType, fetch, SaveFormat } from '@markdownee/markdownee';

// formats default: ['markdown']
const { markdown } = await fetch('https://example.com');

const contents = await fetch('https://example.com', {
  formats: [SaveFormat.Markdown, SaveFormat.MinifiedHtml, SaveFormat.Original],
  crawlerType: CrawlerType.Cheerio,
});
```

The result is a map; request failure throws and unavailable formats are omitted.
`SaveFormat` and `SAVE_FORMATS`
describe `txt`, `markdown`, `html`, `minified-html`, and `original`; compact
HTML appears under `minifiedHtml`. The single-page subset excludes `save`,
`storageDir`, `includeHtml`, and crawl-frontier controls. Request `original`
through `formats` instead. Image `save` is rejected by this return-only API.

Raw strings and alias-object members serialize to the same wire values.

The root entry provides extraction and its types and vocabulary. Import CLI
construction from `@markdownee/markdownee/cli`, storage tools from
`@markdownee/markdownee/storage`, and Zod validators from
`@markdownee/markdownee/schema`. The validators
`MarkdowneeLibraryInput` and `MarkdowneeFetchInput` own the corresponding
option defaults and validation. Importing these entry points does not execute a CLI command.

### Export and purge: `runExportAction`, `runPurgeAction`

The storage commands also have library functions:

```typescript
import { runExportAction, runPurgeAction } from '@markdownee/markdownee/storage';

const exported = await runExportAction({
  outputDir: './out',
  storageDir: './my-archive',
});
console.log(exported.filesWritten, 'files —', exported.manifestPath);

const purged = await runPurgeAction({ storageDir: './my-archive' });
console.log('purged', purged.storageDir);
```

`runExportAction(opts: ExportOpts): Promise<ExportResult>` accepts `outputDir`
(default `./markdownee-output`) and `storageDir`, returning
`{ outputDir, filesWritten, recordsTotal, manifestPath }`.
`runPurgeAction(opts?: PurgeOpts): Promise<PurgeResult>` accepts `storageDir`
and returns `{ storageDir }` after deleting the buckets. Both use CLI-compatible
path resolution and return rather than calling `process.exit()`.

## Library use (Crawlee re-exports)

Configure the storage directory before opening the re-exported Crawlee stores.
An incorrect directory can yield a different or empty dataset.

```typescript
import {
  configureStorage,
  resolveStorageDir,
  Dataset,
  KeyValueStore,
  Configuration,
} from '@markdownee/markdownee/storage';

// Point Crawlee at the dir the CLI wrote to (./storage, else the XDG
// dir); resolveStorageDir() finds it — the same rule the CLI uses.
configureStorage(resolveStorageDir());

const ds = await Dataset.open('my-dataset');
await ds.forEach((item) => console.log(item));

const kvs = await KeyValueStore.open('default');
const value = await kvs.getValue('my-key');
```

## Requirements

- **Node.js 22.22.2+ on the 22 line, 24.15.0+ on the 24 line, or 26+.**
  The extraction engine is JavaScript. Image saving
  loads [sharp](https://sharp.pixelplumbing.com/), whose platform dependencies
  supply native image processing.
- **A Playwright browser for browser crawling:** Chromium for adaptive/Chromium,
  Firefox for Firefox. HTTP-only Cheerio needs neither.
